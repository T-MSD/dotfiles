# dotfiles

Personal macOS configuration for Neovim, Ghostty, tmux, WezTerm and JankyBorders, plus a `theme` command that switches Ghostty, tmux and Neovim to the same colour scheme in one step.

This repo is the source of truth: `install.sh` symlinks each config into `$HOME`, so any change made locally is already a change in the repo. Commit and push.

## Contents

| Folder | Linked to | What it is |
|---|---|---|
| [`nvim/`](nvim/README.md) | `~/.config/nvim` | LazyVim-based Neovim config |
| `ghostty/` | `~/.config/ghostty` | Ghostty terminal config and custom jellybeans themes |
| `tmux/` | `~/.config/tmux` | tmux theme output and local plugins |
| `tmux/.tmux.conf` | `~/.tmux.conf` | Main tmux config |
| `theme/` | `~/.config/theme` | Theme definitions and templates used by the `theme` command |
| `theme/bin/theme` | `~/.local/bin/theme` | The `theme` command |
| `borders/` | `~/.config/borders` | [JankyBorders](https://github.com/FelixKratz/JankyBorders) window border config |
| `wezterm/.wezterm.lua` | `~/.wezterm.lua` | WezTerm config |
| `mount_external.sh` | not linked | Linux helper that mounts an NTFS partition by UUID |

## Install

### Prerequisites

```sh
brew install neovim tmux fzf ripgrep fd
brew install --cask ghostty font-fira-code-nerd-font
brew install FelixKratz/formulae/borders

# tmux plugin manager
git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm

# pane-notify (sourced by .tmux.conf)
git clone https://github.com/T-MSD/pane-notify ~/repos/dev/pane-notify
```

Ruby projects use the `ruby-lsp` from rbenv rather than Mason, so run `gem install ruby-lsp` in each Ruby version you use.

### Link the configs

```sh
git clone https://github.com/T-MSD/dotfiles ~/repos/dev/dotfiles
cd ~/repos/dev/dotfiles
./install.sh
```

The script:

- links every entry in its `LINKS` list into `$HOME`,
- moves anything already at a target to `<target>.bak` (or `<target>.bak.<timestamp>` if a backup exists),
- skips links that are already correct, so it is safe to re-run.

Directories are linked whole rather than file by file. The `theme` command replaces its generated files with `mv`, which would silently replace a file-level symlink with a regular file.

### First run

```sh
theme jellybeans-hc        # generate the theme files (they are not tracked)
tmux                       # then press prefix + I to install TPM plugins
nvim                       # lazy.nvim installs plugins on first start
```

`~/.local/bin` must be on your `PATH` for `theme` to resolve.

## Day-to-day

Edit configs where they live (`~/.config/nvim`, `~/.tmux.conf`, ...). The edits land in this repo:

```sh
cd ~/repos/dev/dotfiles
git status
git commit -am "chore(nvim): ..."
git push
```

To track a new config, copy it into the repo, add a `"<repo path>:<path under $HOME>"` line to `LINKS` in `install.sh`, and re-run the script.

## Theme switching

`theme` writes one generated file per tool and reloads whatever is running:

| Tool | Generated file | Reload |
|---|---|---|
| Ghostty | `ghostty/theme.conf` | `SIGUSR2` to Ghostty |
| tmux | `tmux/theme.conf` (from `theme/templates/tmux.conf.in`) | `tmux source-file` |
| Neovim | `nvim/lua/config/theme.lua` | `:ThemeReload` in every running instance |

```sh
theme                      # fzf picker over all themes, with live preview
theme gruvbox              # pick a flavour within a family
theme rose-pine moon       # apply family + flavour
theme tokyonight-night     # apply by full name
theme toggle               # switch light <-> dark within the current family
theme list                 # print every theme with colour swatches
```

Available families: gruvbox, jellybeans, melange, rose-pine, tokyonight, vesper.

The generated files, `theme/current` and `theme/last/` are git-ignored, so switching themes never leaves the repo dirty. Each tool tolerates the file being missing: Ghostty uses `config-file = ?theme.conf`, tmux uses `source-file -q`, and Neovim falls back to gruvbox.

### Adding a theme

1. Create `theme/themes/<family>-<flavour>.sh` defining `FAMILY`, `FLAVOUR`, `APPEARANCE`, `GHOSTTY_THEME`, the `NVIM_*` variables and the twelve `TM_*` colours. Copy an existing file as a starting point. `GHOSTTY_BG` and `NVIM_MODULE` are optional.
2. `GHOSTTY_THEME` must be a theme Ghostty knows (`ghostty +list-themes`). Put custom ones in `ghostty/themes/`.
3. For a new family, add a plugin spec in `nvim/lua/plugins/themes/<family>.lua`.

## tmux

- Prefix is `C-a`.
- `prefix |` and `prefix -` split horizontally and vertically.
- `prefix h/j/k/l` resizes panes; `prefix m` zooms.
- `prefix r` reloads `~/.tmux.conf`.
- `C-Tab` / `C-S-Tab` cycle sessions without the prefix. Ghostty sends these as escape sequences, see the keybinds in `ghostty/config`.
- Status bar is at the top and is generated by `theme`.
- Plugins: [tpm](https://github.com/tmux-plugins/tpm), [vim-tmux-navigator](https://github.com/christoomey/vim-tmux-navigator), [tmux-battery](https://github.com/tmux-plugins/tmux-battery).
- Local plugins:
  - `tmux/plugins/cc-auto-rename-window` names windows running Claude Code after the session title. It lives outside `~/.tmux/plugins` so TPM's clean does not remove it.
  - [pane-notify](https://github.com/T-MSD/pane-notify) shows badges and notifications when a long command finishes or an agent is waiting for input.

## Ghostty

FiraCode Nerd Font at 18pt, no window decorations, left Option as Alt. The theme is set only through the generated `theme.conf`; do not add `theme =` to `ghostty/config`.

## WezTerm

Kept as an alternative to Ghostty. It is not managed by `theme` and uses the built-in `GruvboxDarkHard` scheme.
